# FinApp ERP — Цех приправ (Seasoning Factory)

Веб‑приложение и Telegram Mini App для учёта на мини‑заводе приправ: закупки сырья,
производственные прогоны с расчётом себестоимости (WAC), склад готовой продукции,
передача на главный завод. Интерфейс на русском, валюта — UZS.

## Архитектура (всё на Railway)

```
Браузер / Telegram Mini App  (webapp/index.html)
            │  POST /api   (тот же домен)
            ▼
Railway  (app.py)  ── веб‑сервер + API + Telegram‑бот (один процесс)
            │  SQL
            ▼
PostgreSQL  (Railway plugin)  ── база данных
```

- **PostgreSQL** — источник данных (быстро). Схема создаётся автоматически при старте.
- **`app.py`** — отдаёт сам webapp, обслуживает `POST /api` (JSON‑экшены) напрямую из
  Postgres и запускает Telegram‑бота в фоновом потоке. Бот вызывает те же обработчики
  внутри процесса (без сети).
- Никаких Google Sheets / Apps Script. Один запрос «браузер → Railway → Postgres»,
  типичная задержка `bootstrap` ≈ единицы–десятки миллисекунд.

## Два завода

Приложение обслуживает **два цеха**: `seasoning` (Цех приправ) и `main` (Главный завод).
У каждого свои материалы, продукция, склад, история и отчёты. Владелец и менеджер
переключаются между цехами (переключатель в шапке); цеховые роли видят только свой цех.

- **Передача между цехами.** Цех приправ передаёт продукцию на главный завод
  («Передать на главный завод» — доступно и работнику цеха). Переданная приправа
  автоматически приходуется на склад сырья главного завода со своей себестоимостью
  и сразу доступна для производства (единая цепочка затрат).
- **Компаунды (составное сырьё).** При добавлении материала менеджер может отметить
  «компаунд» и задать состав (напр. Мука 4кг, Соль 1кг на партию). В производстве
  компаунд выбирается как одна строка (× кол-во партий); система сама списывает
  компоненты со склада и считает их стоимость. Отдельный остаток компаунда не ведётся.
- **Отчёты** (Владелец/Менеджер) — отдельная вкладка: по каждому цеху за период
  (сегодня/месяц/всё) — выпуск, себестоимость, закупки, оценка склада, разбивка по продуктам.

### Роли

| Роль | Доступ |
|---|---|
| **seasoning** (Цех приправ) | Цех приправ: закупки (без цены), производство, передача на главный завод, остатки без цен |
| **main** (Главный завод) | Главный завод: закупки (без цены), производство, остатки без цен |
| **manager** (Менеджер) | Оба цеха: цены, себестоимость, отчёты, пороги, управление материалами/SKU/пользователями |
| **owner** (Владелец) | Полный доступ к обоим цехам + редактирование/удаление записей + отчёты + переключатель ролей |

## Бизнес‑логика

- **Производственный прогон (главная операция)**: цех выбирает продукт, вводит сколько
  пачек выпущено и список израсходованного сырья (материал + количество + единица).
  За одну операцию: списывается сырьё, приходуется готовая продукция, считается
  себестоимость по WAC. Пример: 50 кг упаковки (WAC 10 000) + 20 кг специй (WAC 50 000)
  → 10 000 пачек = 1 500 000 сум → **150 сум/пачка**.
- **Остаток сырья** = Σ закупок − Σ расхода. **Готовая продукция** = Σ выпуска − Σ передач (в пачках).
- **WAC** = Σ(подтверждённые суммы закупок) / Σ(подтверждённый объём).
- **Низкий остаток**: остаток < порога (`low_stock_threshold` > 0) → баннер. По умолчанию пороги = 0.
- **Подтверждение цены**: цех записывает закупку без цены; менеджер подтверждает сумму → формируется WAC.

## Развёртывание на Railway

> Нужны: GitHub (этот репозиторий), Railway, токен бота от @BotFather.

1. **Создайте проект**: https://railway.app → New Project → Deploy from GitHub repo →
   выберите `blaze1235/finapp-maccaldo` (ветка `claude/eager-volta-mrkhuq`). Соберётся по `Dockerfile`.
2. **Добавьте базу**: в проекте → **+ New → Database → PostgreSQL**. Railway сам
   выставит переменную `DATABASE_URL` сервису.
3. **Переменные сервиса** → Variables:
   ```
   BOT_TOKEN = <токен от @BotFather>
   ```
   (`DATABASE_URL` — автоматически; `WEBAPP_URL` — из `RAILWAY_PUBLIC_DOMAIN`.)
4. **Публичный домен**: Settings → Networking → **Generate Domain**.
5. Готово. Проверка: `https://<домен>/health` → `{"status":"ok","version":"4"}`.
   Откройте домен в браузере (войдите по Telegram ID `1398614118`) или отправьте боту **/start**.

### Переменные окружения

| Переменная | Обязательно | Значение |
|---|---|---|
| `DATABASE_URL` | да | Автоматически от PostgreSQL‑плагина Railway |
| `BOT_TOKEN` | да (для бота) | Токен @BotFather |
| `WEBAPP_URL` | нет | Публичный URL (иначе из `RAILWAY_PUBLIC_DOMAIN`) |
| `WEB_ACCESS_CODE` | нет | Общий код для веб‑входа (не Telegram) |
| `PORT` | нет | Railway задаёт сам |

## Заполнение данными

Войдите как владелец/менеджер → **⚙️ Настройки**: добавьте материалы (название,
базовая единица, единицы ввода `кг:1, мешок 25кг:25`, порог), продукты (SKU: вес,
пачек в коробке) и пользователей (Telegram ID, имя, роль).

## Локальный запуск

```bash
pip install -r requirements.txt
# поднимите локальный Postgres и укажите DATABASE_URL
DATABASE_URL="postgresql://user:pass@localhost:5432/finapp" PORT=8080 python app.py
# откройте http://localhost:8080
```
`BOT_TOKEN` можно не задавать — поднимется только webapp + API.
